# hive-to-s3-snapshot-load

Демонстрационный проект: загрузка текущих цен из дневного снимка в S3-совместимом хранилище вместо таблицы Hive. Бизнес-результат остаётся тем же: цены попадают в таблицу PostgreSQL.

## Что показывает проект

- Переключение источника: чтение ORC-файлов дневной партиции из S3 вместо Hive-таблицы.
- Определение нужной партиции в Airflow и проверку, что в ней есть данные.
- Запуск Spark-приложения из DAG вместе с пакетом собственного кода.
- Проверку данных перед записью: пустые ключи, некорректные цены и дубли не отбрасываются молча, а останавливают загрузку.
- Безопасный повторный запуск: перед записью удаляются строки той же даты.
- Хранение секретов вне кода: параметры берутся из Airflow Connections и Variables.

## Идея миграции

```text
Было:    Hive-таблица -> Spark -> PostgreSQL
Стало:   дневной снимок ORC в S3 -> Spark -> PostgreSQL
```

Снимок лежит по пути вида `warehouse/prices/current_price/dataflow_date=YYYY-MM-DD/`. Дата в названии партиции — предыдущий календарный день относительно запуска.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `dags/price_load_dag.py` | Airflow DAG: поиск партиции, очистка даты, запуск Spark |
| `jobs/price_job.py` | Spark-приложение: чтение ORC, проверки, запись в PostgreSQL |
| `price_load/partitions.py` | Расчёт даты партиции и проверка наличия ORC-файлов |
| `price_load/transform.py` | Нормализация данных и проверки качества |
| `price_load/config.py` | JDBC-настройки из переменных окружения и проверка даты |
| `scripts/build_package.py` | Сборка `dist/price_load.zip` для передачи в Spark |
| `tests/` | Тесты партиций, конфигурации, сборки пакета и преобразований |
| `requirements.txt` | Зависимости |

## Как работает загрузка

1. DAG `load_current_prices` запускается каждый день в 07:20 по московскому времени.
2. Задача `resolve_partition` вычисляет дату предыдущего дня, ищет в бакете файлы `.orc` этой партиции и возвращает путь и дату. Если файлов нет, задача падает с понятной ошибкой.
3. Задача `clear_snapshot_date` удаляет из `ref.current_prices` строки с этой `load_date`.
4. Задача `load_prices` запускает Spark-приложение. Пакет `price_load.zip` передаётся через `py_files`.
5. Приложение читает ORC, проверяет, что данные не пустые, приводит типы и добавляет `load_date`. Если найдены пустые ключи, некорректные или отрицательные цены либо дубли ключей `item_id` и `shop_id`, оно останавливается до записи.
6. Результат записывается в PostgreSQL по JDBC.

Названия таблиц и колонок вымышленные. Колонка `load_date` добавлена в демо ради повторных запусков.

## Подключения и секреты

В репозитории нет паролей, ключей и реальных адресов. Нужны:

- Connection `s3_snapshots` — ключи доступа и адрес S3-совместимого хранилища (`endpoint_url` в поле Extra);
- Connection `pg_target` — параметры PostgreSQL;
- Connection `spark_default` — настройки запуска Spark;
- Variable `snapshot_bucket` — имя бакета.

Значения подставляются при запуске и передаются приложению через переменные окружения. Для боевого окружения лучше использовать secrets backend или роли доступа вместо ключей в параметрах запуска.

## Как подготовить запуск

```bash
python scripts/build_package.py
```

Команда создаёт `dist/price_load.zip`. Скопируйте архив и `jobs/price_job.py` в каталог, указанный в DAG (`/opt/airflow/jobs`). Пакет `price_load` должен быть доступен Airflow при разборе DAG, например лежать рядом с папкой `dags`.

## Запуск тестов

```bash
python -m unittest discover -s tests -t .
```

Тесты преобразований требуют установленного PySpark, без него они пропускаются.

## Версии

Рекомендуемые версии (проверьте на своём окружении): Python 3.9 или 3.10, PySpark 3.3.1, Apache Airflow 2.6.3 с провайдерами Amazon, Spark и Postgres. Для чтения `s3a://` нужны `hadoop-aws` и `aws-java-sdk-bundle`, совместимые с версией Hadoop в Spark. Для Hadoop 3.3.2 это обычно `hadoop-aws` 3.3.2 и `aws-java-sdk-bundle` 1.11.1026.

## Ограничения

- Проект не запускался целиком в связке Airflow, Spark, S3 и PostgreSQL.
- Очистка и запись выполняются отдельными шагами и не образуют одну транзакцию. После сбоя повторный запуск заново удалит и загрузит данные этой даты.
- В демо ключи S3 передаются Spark через переменные окружения драйвера и исполнителей. Для промышленной эксплуатации нужен более безопасный способ.
- Настройки Spark и S3 зависят от среды выполнения, их нужно проверить отдельно.
- Проект показывает подход к миграции, а не готовое решение для промышленной эксплуатации.
